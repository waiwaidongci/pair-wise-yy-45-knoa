# 服装品牌打样开发与版型修订工作台

为服装产品开发团队提供款式档案、样品轮次、尺寸实测、部位批注、替代改版方案、审核锁定和修订历史。

## 技术栈

React + MUI + Redux Toolkit + RTK Query + React Router + MSW + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62045`。

## 核心工作流

- 从款式档案进入开发轮次，维护尺码、面辅料、色卡和工艺要求。
- 对比两轮尺寸实测，自动高亮超出容差的部位并关联试穿意见。
- 点击样衣图片部位添加批注，或由版师提交替代方案和责任人。
- 负责人采纳方案、填写未提交草稿，审核完成后锁定轮次并保留完整历史。

## 依赖链（尺寸/批注 → 工艺要求 → 样衣结论）

所有资料挂在同一条版本化依赖链上，避免工厂按过时资料开裁：

- **源版本**：每个部位的尺寸规格与批注各带版本号；提交"尺寸新决定/批注新决定"后该部位源升版。
- **选择性失效**：工艺要求声明所依赖的部位（`dependsOn`）及其依据版本；源变更后只有相关工艺变为「待重算」，未受影响部分继续沿用。
- **结论幂等重算**：样衣通过标记逐部位与所依据的规格/批注版本绑定，提交后只重算受影响部位；同版本重复提交不会产生第二条标记。
- **责任人再确认**：责任人对过期工艺可给出「继续沿用」（为当前版本差异背书）或「已更新」（推进依据版本），结果写入履历；源再次变更会重新失效。
- **并发提交**：链版本做乐观锁；两人同交时先提交版本留下，后提交者收到 409，可看到被改部位与双方差异，合并后基于新版本重提。
- **写入断点**：写入失败时已选部位保留为断点（localStorage 持久化，刷新仍在）；恢复时从断点重做，spec/批注与通过标记均不重复执行/生成。

评审台「部位修订依赖链 · 提交」面板提供两个演示开关：*模拟两人同交* 与 *模拟写入失败*。
档案页、评审台、履历区均以过期横幅/徽章标注过期部位、受影响工艺、过期通过标记以及责任人的再确认结果。
